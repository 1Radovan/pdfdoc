Документ описывает, что нужно для работы пакета `pdfdoc`, что он делает, в каком
формате отдаёт результат и где его границы. Его можно использовать как ТЗ при
встраивании в другое приложение и как чек-лист при развёртывании.

## 1. Назначение и границы

`pdfdoc` превращает PDF-документ в объект `Document` (pydantic v2) и JSON-файл:

- список логических блоков с типом, координатами, текстом и уверенностью распознавания:
  заголовки, абзацы, пункты списков, таблицы, подписи, колонтитулы, номера страниц, картинки;
- таблицы в трёх видах: матрица ячеек (`table_cells`), markdown (`table_md`) и HTML
  с `rowspan`/`colspan` (`html`), плюс список объединённых ячеек и уверенность по каждой ячейке;
- навигацию по страницам (`pages`): способ обработки страницы, её блоки и таблицы,
  исправленный перекос и поворот;
- предупреждения (`warnings`) о местах, которые стоит проверить человеку.

Загрузка результата в любом месте приложения:

```python
doc = Document.model_validate_json(json_str)
```

Пакет работает **офлайн**: сеть не нужна, документы никуда не отправляются.

**Вне рамок:** рукописный текст; извлечение полей по шаблону (ИНН, суммы и т.п.) —
это следующий слой поверх блоков; таблицы без линий сетки на сканах (см. п. 11);
формы AcroForm и аннотации; DOCX/XLSX и изображения не в PDF (JPG/TIFF нужно сначала
обернуть в PDF).

## 2. Окружение: ОС, Python, ресурсы

| Параметр | Требование | Примечание |
|---|---|---|
| ОС | Linux x86_64/arm64 (основная), Windows 10+, macOS 12+ | Проверено на Linux (Debian/Ubuntu) |
| Python | **3.10–3.13** | Тесты пройдены на 3.11 и 3.13; ниже 3.10 не поддерживается (синтаксис типов, pydantic v2) |
| CPU | от 2 ядер; для пакетной обработки — чем больше, тем лучше | OCR масштабируется почти линейно по процессам |
| RAM | **~300 МБ на рабочий процесс** при 300 dpi (A4) | При 400 dpi измерено 330 МБ; страницы рендерятся по одной, память не растёт с числом страниц |
| Диск | рядом с PDF — JSON ≈ 5–50 КБ на страницу | Временные файлы Tesseract — в системной temp-папке, удаляются сразу |
| Права | чтение PDF, запись в папку JSON (по умолчанию — папка с PDF) | Запись атомарная: временный файл → rename |

### Измеренная производительность

Тестовый стенд: 2 vCPU, Tesseract 5.3.4, 300 dpi.

| Документ | Время | Пиковая память процесса |
|---|---|---|
| PDF с текстовым слоем, 2 стр. (2 таблицы) | 0,5 с (≈0,25 с/стр.) | 70 МБ |
| Скан, 2 стр. (2 таблицы по 20–25 ячеек + текст) | 9,2 с при `ocr_threads=2`, 12,7 с при 1 | 300 МБ |
| Скан, 1 стр., плотная таблица (14×7, 83 непустые ячейки, объединения) | 9,4 с при `ocr_threads=2`, 15,9 с при 1 | 265 МБ |

Для оценки больших объёмов: **скан ≈ 5–10 с на страницу на одно ядро** (зависит от
числа ячеек), текстовый слой — доли секунды. Например, 10 000 страниц сканов на
8 ядрах (8 процессов) займут ≈ 1,7–3,5 часа.

> ⚠️ **Лицензия PyMuPDF — AGPL-3.0.** Если приложение распространяется или
> предоставляется по сети как сервис и его код не открывается под AGPL, нужна
> коммерческая лицензия Artifex. Вопрос стоит решить с юристами до промышленного

Установка:

```bash

pip install -r requirements.txt          # или: pip install .
pip install -r requirements-dev.txt      # для тестов
```

В конфликтном окружении, где уже стоит `opencv-python` с GUI: два пакета OpenCV
одновременно ставить нельзя, оставьте один (подойдёт любой).

## 4. Системные зависимости: Tesseract

Нужен **только если в PDF есть сканы** (страницы без текстового слоя или с битым
слоем). PDF с нормальным текстовым слоем обрабатываются без Tesseract. Если OCR
понадобился, а Tesseract не установлен, вызов завершится понятным исключением
`TesseractNotAvailableError` с подсказкой. Пустой результат «молча» не возвращается.

| Компонент | Требование |
|---|---|
| Tesseract | **4.0+ (LSTM)**, рекомендуется **5.3+**. Проверено на 5.3.4 |
| Языковые данные | `rus` и `eng` — обязательно (по умолчанию `ocr_lang="rus+eng"`); `osd` — для определения поворота страницы на 90/180/270 (без него поворот не исправляется, остальное работает) |

### Установка

**Debian/Ubuntu** (в Docker-образе на `python:*-bookworm` — так же):
```bash
sudo apt-get install -y tesseract-ocr tesseract-ocr-rus tesseract-ocr-eng tesseract-ocr-osd
```

**RHEL/Alma/Rocky 8–9** (пакеты из EPEL; названия языковых пакетов зависят от версии —
проверьте `dnf search tesseract`):
```bash
sudo dnf install -y epel-release
sudo dnf install -y tesseract tesseract-langpack-rus
```

**macOS:** `brew install tesseract tesseract-lang`

**Windows:** установщик UB Mannheim (github.com/UB-Mannheim/tesseract/wiki). При
установке отметьте Russian в *Additional language data*. Путь
`C:\Program Files\Tesseract-OCR\tesseract.exe` находится автоматически. Другой путь
укажите в переменной `TESSERACT_CMD` или в `PipelineConfig(tesseract_cmd=...)`.

### Проверка

```bash
tesseract --version          # 5.x
tesseract --list-langs       # должны быть: eng, osd, rus
```

### Качество моделей

Пакеты дистрибутивов ставят модели *tessdata_fast*. Модели *tessdata_best*
(github.com/tesseract-ocr/tessdata_best) немного точнее на плохих сканах, но в
2–3 раза медленнее. Для них положите `rus.traineddata`/`eng.traineddata` в
отдельную папку и укажите `PipelineConfig(tessdata_dir="...")` или `TESSDATA_PREFIX`.

### Переменные окружения

| Переменная | Назначение |
|---|---|
| `OMP_THREAD_LIMIT` | Пакет ставит `1`, если не задано (`setdefault`). Tesseract вызывается сотни раз на мелких картинках, и многопоточность OpenMP его только замедляет: на 2 ядрах однопоточный режим быстрее на ~25%. Параллельность обеспечивают `ocr_threads` и процессы |
| `TESSERACT_CMD` | Путь к бинарнику Tesseract |
| `TESSDATA_PREFIX` | Папка с `*.traineddata` |

## 5. Требования к входным PDF

**Поддерживаются:**
- PDF с текстовым слоем (выгрузки из 1С, Word, Excel и т.п.);
- сканы: PDF из картинок, в том числе с невидимым текстовым слоем от чужого OCR
  (используется как есть, с пониженной уверенностью 0,9; если слой похож на кириллицу,
  прочитанную латиницей, — «Cqer Ha onnary», — страница распознаётся заново);
- смешанные документы (часть страниц текстом, часть сканом) — каждая страница
  обрабатывается своим способом;
- страницы с `/Rotate` и сканы, повёрнутые на 90/180/270 (нужен `osd`);
- лист, развёрнутый поворотом содержимого без флага `/Rotate` (альбомная таблица на
  книжной странице или наоборот), — в текстовом слое и на скане, в том числе когда
  на одной странице обычный текст и повёрнутая таблица;
- перекос скана до ±5° (настраивается `max_skew_deg`);
- сдвиг листа при сканировании (вертикали сетки наклонены при ровных горизонталях,
  поворотом страницы не исправляется) и «веер» горизонталей — до ±3°: у каждой линии
  сетки свой наклон.

**Рекомендации к сканам:** 300 dpi (минимум 200), оттенки серого или ч/б, таблицы с
видимыми линиями сетки. Цветной скан допустим: он переводится в оттенки серого.

**Не поддерживаются / ошибка:** PDF с паролем на открытие (`PdfOpenError`),
повреждённые файлы (`PdfOpenError`). Ошибка в одном файле при пакетной обработке не
останавливает пачку и попадает в отчёт.

## 6. Функциональные требования

| № | Требование |
|---|---|
| FR-1 | На вход — путь к PDF (`process_pdf`), байты (`process_bytes`) или папка/список файлов (`process_folder`) |
| FR-2 | Для каждой страницы определяется способ обработки: текстовый слой, OCR или «пустая». OCR выбирается, если текста меньше `min_text_chars` и есть изображения или векторная графика (текст «в кривых»), либо доля битых символов больше `max_garbage_ratio` (кракозябры, U+FFFD, Private Use Area, `(cid:NN)`), либо невидимый слой чужого OCR похож на кириллицу, прочитанную латиницей (кириллицы меньше 25% букв, а английских служебных слов — меньше 15% слов; `check_hidden_text_layer`), либо задан `force_ocr` |
| FR-3 | Текстовый слой: блоки PyMuPDF дробятся по смене кегля, большим зазорам и началу пункта списка («2. …», «3.1. …», «4) …», «• …»). Сохраняются кегль и доля жирного — по ним определяются заголовки |
| FR-4 | Таблицы текстового слоя — через `find_tables` по линиям. Объединённые ячейки восстанавливаются по геометрии (`rowspan`/`colspan`). Текст таблиц не дублируется в текстовых блоках. Строки и столбцы таблицы определяются по направлению строк текста внутри неё (`dir` у строк PyMuPDF), порядок чтения страницы — по направлению текста вне таблиц: так читаются листы, повёрнутые поворотом содержимого без `/Rotate` |
| FR-5 | OCR-страница: растеризация (`dpi`, по умолчанию 300) → исправление поворота на 90/180/270 (OSD; если уверенность OSD ниже 2, поворот принимается, только когда после него пробное распознавание в `psm 6` даёт в 1,5 раза больше уверенно прочитанного текста) → исправление перекоса (поиск угла по проекциям, точность 0,02°). Таблица, занимающая меньше половины страницы, проверяется на поворот отдельно (OSD по вырезке + обязательная сверка): повёрнутая вырезка разворачивается, сетка в ней ищется заново |
| FR-6 | Таблицы на скане: маски горизонтальных и вертикальных линий → связные компоненты (несколько таблиц на странице) → сетка (проекции вдоль общего наклона линий, затем прямая для каждой линии) → объединения в обе стороны (union-find по отсутствующим границам, границы проверяются вдоль наклонных линий). Рамка листа (ГОСТ, края скана) не считается таблицей, внутри неё ищутся таблицы; таблица внутри рамки выдаётся один раз |
| FR-7 | Ячейки скана распознаются параллельно (`ocr_threads`): сетка стирается по маске линий, остатки линий у краёв ячейки — только вдоль своего края (горизонтальные у верхнего/нижнего, вертикальные во всю высоту у левого/правого: штрихи цифр и букв у края не стираются), текст обрезается по чернилам с белым полем, увеличивается только мелкий текст (< 20 px), прочерк определяется геометрически, числовые ячейки перепроверяются с белым списком цифр и перечитываются с более светлым порогом бинаризации (засечки «1», тонкие части «0»). В числовой колонке «палочки» («\|», «I», «]», …) заменяются на «1» с уверенностью 0,6. В русской таблице короткие латинские ячейки («Kr», «UIT.») перечитываются только русской моделью и заменяются, если вышло слово кириллицей с уверенностью ≥ 0,5 («кг», «шт.»). Явно испорченные разделители тысяч в суммах («1. 550,00», «1,490,00», «1.317 500,00») заменяются пробелами; согласованные форматы («1.905,00», «1,905.00») не трогаются. Многострочный текст ячейки склеивается в строку; перенос после дефиса («ГОСТ 1000-\n99») и число, перенесённое в узкой ячейке («4 321.5\n6»), склеиваются без пробела |
| FR-8 | Текст вне таблиц — Tesseract `psm 3` с координатами слов; абзацы дробятся по скачку высоты строки, зазорам и началу пункта списка; мусор от пятен и линий отбрасывается |
| FR-9 | Латинские двойники внутри кириллических слов и инициалов («Cтанoк», «A.B.») заменяются на кириллицу (`fix_homoglyphs`) |
| FR-10 | Тип блока определяется эвристиками: номер страницы (в полях), подпись (черта/«подпись»/«М.П.» + должность/инициалы/«/Фамилия/»), заголовок (кегль, жирность, ПРОПИСНЫЕ), пункт списка, текст. Колонтитулы — текст у краёв, повторяющийся на ≥ половине страниц |
| FR-11 | Порядок блоков — порядок чтения (сверху вниз, на одной высоте — слева направо) в «выпрямленных» координатах; `block_id = p{страница}_b{NN}` |
| FR-12 | Уверенность (`confidence`) есть у каждого блока и у каждой ячейки OCR-таблицы (см. п. 7.4) |
| FR-13 | Предупреждения: низкая уверенность, пустые ячейки в колонках, нечитаемые ячейки, битый текстовый слой, невидимый слой чужого OCR, поворот скана или таблицы, сомнительный поворот, ошибка страницы, пустая страница, обрезка по `max_pages` (полный список — в п. 7.5) |
| FR-14 | JSON сохраняется **рядом с PDF** (`имя.json`) или в `output_dir`; запись атомарная |
| FR-15 | Повторный запуск не пересчитывает файл, если рядом лежит JSON с тем же `file_hash` (SHA-256 PDF) и `pipeline_version` (`skip_existing`) |
| FR-16 | Ошибка одной страницы не ломает документ (страница помечается `failed`, причина — в `warnings`). Отсутствие Tesseract, битый или зашифрованный PDF — исключение |
| FR-17 | Пакетная обработка — в нескольких процессах, с отчётом `BatchReport` (обработано/пропущено/ошибки по каждому файлу) |
| FR-18 | CLI: `python -m pdfdoc <файлы/папки> [--out DIR] [--workers N] [--force] [--force-ocr] [--dpi N] [--lang L] [--no-tables] [--report FILE] [--schema]` |

## 7. Формат результата (JSON)

Полная машиночитаемая схема — `schema/document.schema.json` (генерируется
`python -m pdfdoc --schema`). Пример — `examples/vedomost_scan.json`. Ваш эталонный
пример `examples/example_from_spec.json` проходит валидацию без изменений.

### 7.1 Document

| Поле | Тип | Описание |
|---|---|---|
| `file_name` | str | Имя PDF |
| `file_hash` | str | SHA-256 содержимого PDF (hex) — ключ идемпотентности |
| `total_pages` | int | Страниц в PDF |
| `pipeline_version` | str | Версия pdfdoc |
| `processing_time_ms` | int | Время обработки |
| `warnings` | list[str] | Предупреждения (п. 7.5) |
| `blocks` | list[Block] | Блоки всех страниц в порядке чтения |
| `pages` | list[PageInfo] | *Расширение.* Навигация по страницам |
| `schema_version` | str | *Расширение.* Версия формата (`1.0`) |

### 7.2 Block

| Поле | Тип | Описание |
|---|---|---|
| `page` | int | Страница, с 1 |
| `block_id` | str | `p{page}_b{NN}` |
| `type` | enum | `header`, `text`, `list_item`, `table`, `signature`, `page_header`, `page_footer`, `page_number`, `image` |
| `bbox` | [x0, y0, x1, y1] | Пункты PDF (1/72″), начало — левый верхний угол **страницы как она отображается** (с учётом `/Rotate`). Для повёрнутого скана bbox описывает место на странице, а порядок блоков считается по выпрямленному изображению |
| `text` | str \| null | Текст блока (для таблиц — null). Строки абзаца склеены пробелом, перенос с дефисом — без пробела |
| `table_md` | str \| null | Таблица в markdown, первая строка — шапка |
| `table_cells` | list[list[str]] \| null | Прямоугольная матрица. Объединённая ячейка: текст в левой верхней, остальные `""` (или повтор, если `merged_cell_fill="repeat"`) |
| `html` | str \| null | `<table>` с `rowspan`/`colspan` — без потерь структуры |
| `confidence` | float 0..1 | См. 7.4 |
| `source` | enum | `text_layer`, `ocr`, `table_extractor` (таблица текстового слоя), `table_ocr` (таблица скана) |
| `language` | str \| null | `ru`, `en`, `mixed`; null — в блоке нет букв |
| `table_spans` | list \| null | *Расширение.* Только объединённые ячейки: `{row, col, rowspan, colspan}` (с нуля) |
| `table_cell_confidence` | list[list[float\|null]] \| null | *Расширение.* Уверенность OCR по ячейкам, та же форма, что `table_cells`; null — пусто или перекрыто объединением; 0.0 — изображение есть, текст не прочитан |

### 7.3 PageInfo (`pages[]`)

`page`, `width`, `height` (пт, как отображается), `rotation` (`/Rotate`), `source`
(`text_layer`/`ocr`/`empty`/`failed`), `confidence` (средняя по блокам),
`skew_angle` (исправленный перекос, °), `orientation` (найденный поворот скана),
`block_ids`, `table_ids`.

### 7.4 Что означает `confidence`

| Источник | Как считается |
|---|---|
| `text_layer` | 0,99. Для невидимого слоя чужого OCR — `hidden_text_layer_confidence` (0,9). Снижается пропорционально доле битых символов в блоке |
| `table_extractor` | 0,95 × уверенность текстового слоя (структура по векторным линиям надёжна, но не идеальна) |
| `ocr` | Средняя уверенность слов Tesseract, взвешенная по длине слова |
| `table_ocr` | Среднее по распознанным ячейкам (нечитаемые = 0) × штраф 0,9, если сетку пришлось чинить (непрямоугольные объединения) |
| `image` | 1,0 (содержимое не распознаётся) |

Уверенность Tesseract — оценка модели, а не вероятность правильности. Что показали
тестовые сканы (332 ячейки, 4 варианта качества):
- верно прочитанные ячейки: от 0,57 до 0,96, большинство 0,9–0,96;
- нечитаемые ячейки: 0,0, мусор на месте прочерка — 0,49–0,74 (порог 0,7 ловит их почти все);
- **замена одной буквы** («мащина», «116330») — 0,9–0,94: уверенность её **не ловит**.

Итог: низкая уверенность — надёжный сигнал «проверить», высокая — не гарантия.
Для важных полей (суммы, ИНН) добавляйте проверки по смыслу: контрольные суммы
«Итого», контрольные цифры ИНН, сверку с другим источником. Порог
`low_confidence_threshold` (0,7) — отправная точка; откалибруйте его на своих
документах (п. 12).

### 7.5 Предупреждения

Строки начинаются с `page N:` — их можно разбирать регулярным выражением.

| Шаблон | Когда |
|---|---|
| `page N: OCR confidence below 0.7 on <type> block <id> (0.63)` | Блок со скана ниже порога (`extraction confidence…` — для текстового слоя) |
| `page N: table <id> column C has K empty cells` | В колонке есть пустые ячейки (без шапки и ячеек под объединениями; полностью пустые колонки не считаются) |
| `page N: table <id> has K unreadable cells` | Изображение в ячейке есть, текст не прочитан |
| `page N: text layer looks damaged (35% bad characters), OCR used` | Битый текстовый слой |
| `page N: invisible text layer (made by another OCR), used as is` | Скан с чужим OCR-слоем |
| `page N: invisible text layer looks like Cyrillic misread as Latin, OCR used` | Чужой OCR-слой непригоден (кириллица прочитана латиницей), страница распознана заново |
| `page N: scan rotated by 90° (orientation fixed)` | Найден и исправлен поворот |
| `page N: scan orientation is uncertain, page processed as is` | OSD предложил поворот с низкой уверенностью, сверка не подтвердила ни один вариант |
| `page N: table rotated by 90° on the page (orientation fixed)` | Таблица на скане повёрнута относительно остального текста страницы |
| `page N: OCR timeout in K table cells` / `page N: text OCR failed: …` | Таймаут Tesseract |
| `page N: processing failed: <Ошибка>: <текст>` | Ошибка страницы (в `pages` — `failed`) |
| `page N: no content recognized` | Страница обработана, но блоков нет |
| `page N: table detection failed: …` | Ошибка `find_tables` |
| `document: P pages, only first M processed (max_pages)` | Сработало ограничение |

## 8. API для встраивания

```python
from pdfdoc import process_pdf, process_bytes, process_folder, Document, PipelineConfig

doc = process_pdf("docs/vedomost_2025_01.pdf")          # JSON → docs/vedomost_2025_01.json
doc = process_pdf(path, PipelineConfig(output_dir="/data/json"))  # JSON в другую папку
doc = process_pdf(path, save=False)                      # без записи на диск
doc = process_bytes(pdf_bytes, "upload.pdf")             # из памяти (например, из HTTP-запроса)

json_str = doc.to_json()                                 # или doc.model_dump_json()
doc = Document.model_validate_json(json_str)             # обратно
doc = Document.load("docs/vedomost_2025_01.json")
doc.save("other.json")                                   # атомарная запись

doc.page_blocks(1); doc.iter_pages(); doc.page_info(2)
doc.tables(); doc.blocks_of_type("signature"); doc.get_block("p1_b03")
doc.low_confidence(0.7); doc.full_text(page=1)

report = process_folder("docs/", workers=8)              # BatchReport
```

**Исключения** (`pdfdoc.errors`): `PdfOpenError` (повреждён/зашифрован),
`TesseractNotAvailableError` (нужен OCR, но нет Tesseract или языка), обе
наследуют `PdfDocError`.

**Потоки и процессы.** `process_pdf`/`process_bytes` можно вызывать из разных потоков
приложения: объекты PyMuPDF не разделяются, Tesseract — отдельные процессы.
`process_folder` с `workers > 1` использует `multiprocessing`, поэтому вызывающий
скрипт должен быть защищён `if __name__ == "__main__":`. В веб-приложении
распознавание лучше выносить в фоновую очередь (Celery/RQ/arq): скан обрабатывается
секунды на страницу, это больше типичных HTTP-таймаутов.

**Логирование** — стандартный `logging`, логгер `pdfdoc`. В stdout пакет ничего не
печатает: подсказка PyMuPDF про `pymupdf_layout` отключается при импорте.

## 11. Известные ограничения

1. **Таблицы без линий сетки на сканах** не распознаются как таблицы: их текст
   попадает в текстовые блоки построчно. Для текстового слоя есть
   `text_table_strategy="text"` (больше ложных срабатываний).
2. **Таблица на несколько страниц** — отдельный блок на каждой странице, склейки нет.
   Повтор шапки на следующих страницах сохраняется как есть.
3. **Многоколоночная вёрстка**: порядок чтения «сверху вниз», колонки газетного типа
   могут перемешаться.
4. **Жирность на сканах не определяется** (LSTM-Tesseract её не отдаёт). Заголовок на
   скане определяется по высоте строки и ПРОПИСНЫМ, поэтому «жирный, того же кегля»
   на скане будет `text`.
5. **Подчёркивания для подписи** (`______`) Tesseract на сканах обычно не выводит.
   Подпись всё равно определяется по «/Фамилия И.О./», должности или горизонтальной
   черте рядом, но в тексте черты не будет.
6. Печати и подписи **поверх текста** снижают качество. Цветные печати можно
   ослабить предобработкой (не реализовано).
7. Эвристика `garbage_ratio` считает символы Latin-1 (À–ÿ) «битыми». Для документов на
   французском и немецком это приведёт к OCR вместо текстового слоя (медленнее, но не
   ошибка). Отключается через `max_garbage_ratio=1.0`.
8. **Скан с хорошим невидимым слоем чужого OCR** (кириллица прочитана верно), где
   сетка таблицы есть только на картинке: слой используется как есть, `find_tables`
   по нему таблицу не находит, и ячейки попадают в текст построчно. Нужен
   гибридный режим (сетка — по картинке, текст ячеек — из слоя), не реализован.
   Свой OCR для таких страниц (`force_ocr`) обычно хуже чужого слоя.
9. Короткие ячейки на сканах (единицы измерения) иногда остаются латиницей или
   читаются с ошибкой в одну букву («ШГ.» вместо «шт.»): у Tesseract в одиночном
   слове нет контекста, словаря единиц в пайплайне нет намеренно.
10. Типы блоков — эвристики, не ML. Для сложной вёрстки можно подключить
   layout-модель на месте `classify.py`: интерфейс `RawBlock` → `BlockType` изолирован.

## 12. Тестирование и приёмка

```bash
pip install -r requirements-dev.txt
pytest -q                    # 51 тест; OCR-тесты пропускаются, если нет Tesseract
```

Что покрыто:
- модели: ваш пример JSON проходит валидацию; round-trip; кириллица без экранирования;
  отказ на неверных bbox, типе, уверенности, рваной таблице, дублях `block_id`;
- текстовый слой: заголовок, абзацы, 2 таблицы (в т.ч. с `rowspan`/`colspan`), пункты
  списка, подписи, номера страниц, предупреждение о пустой ячейке, JSON рядом с PDF,
  `skip_existing`, `output_dir`, `save=False`;
- скан с перекосом 0,8° и шумом: те же таблицы **совпадают с эталоном ячейка в ячейку**,
  перекос найден, уверенность таблицы > 0,85;
- скан листа со сдвигом 2° (вертикали наклонены, горизонтали ровные): таблицы
  совпадают с эталоном; сетка 16×7 с вертикалями под ±0,45° и 1,5° находится без
  ложных объединений;
- «1» без засечек в числовой колонке → «1», в текстовой (римская «I») не трогается;
- штрих буквы у края ячейки не стирается, обрывок линии сетки — стирается;
- таблица внутри рамки листа находится один раз, рамка таблицей не считается;
- невидимый слой «кириллица латиницей» распознаётся как непригодный, английский текст — нет;
- склейка переносов в ячейках (дефис, число в узкой ячейке), испорченные разделители
  тысяч, пробелы в суммах по образцу колонки, латинские «Kr»/«UIT.» в русской таблице,
  начало пункта списка;
- сканы, повёрнутые на 90, 180 и 270°: поворот найден, текст и таблица верные;
- неуверенный ответ OSD (90/180/270): верный поворот принимается, ложный отклоняется;
- текстовый слой, повёрнутый на 90 и 270° внутри альбомного листа без `/Rotate`:
  таблицы, объединения и порядок блоков — как у неповёрнутого оригинала;
- книжный лист с обычным заголовком и альбомной таблицей (строки снизу вверх и сверху
  вниз) — текстом и сканом: таблица совпадает с эталоном, заголовок не повёрнут;
- смешанный PDF (страница текстом + страница сканом);
- страница с текстовым слоем и `/Rotate 90` (у `find_tables` и `get_text` разные системы координат);
- битый PDF: исключение и строка `failed` в отчёте.

Дополнительно (вне тестов) проверено на синтетических сканах Приложения №1 из
«Сверки 1.2» (14×7, вертикальные и горизонтальные объединения, «Итого», 83 непустые
ячейки):

| Скан | Верных ячеек | Ошибки |
|---|---|---|
| чистый | 83 / 83 | — |
| перекос 0,5° | 82 / 83 | «П6330» → «116330» |
| перекос 1° | 83 / 83 | — |
| сильный шум (σ=25 + размытие) | 76 / 83 | 6 прочерков (нечитаемы или «=», отмечены в `warnings`), «машина» → «мащина» |

**Во всех вариантах все числа прочитаны верно.** Для сравнения: исходный OCR из
«Сверки 1.2» на тех же сканах ошибался в суммах на чистом скане (`35,50→35,90`), при
перекосе 0,5° и 1° не находил ни одной позиции, а на шумном скане прочитал
`512,80` как `51280`.

Реальный скан Приложения №1 (`prilozhenie1bilo.pdf`, 10 стр., 78 позиций, 97 строк
мероприятий; лист протянут со сдвигом — вертикали под 0,3–0,5°): в 0.1.0 около трети
строк слипались в одну ячейку (у верхнего и нижнего края таблицы), верных сумм 42 / 97;
в 0.1.1 верны все 97 номеров позиций, количеств, сумм и значений графы 7, а их итоги
совпадают со строкой «Итого». В 0.1.2 тот же результат (97 / 97) и на этом скане,
повёрнутом на 90, 180 и 270°; время — около 45 с на файл. В 0.1.3 — тоже 97 / 97,
в тексте ячеек на 3 ошибки меньше («обооудования» → «оборудования»).

**Рекомендуемая приёмка на реальных документах** (до промышленного запуска):
1. Выборка 30–50 PDF каждого типа (текстовые, хорошие сканы, плохие сканы).
2. Разметить эталон таблиц (ячейки) и ключевых полей.
3. Метрики: доля верных ячеек (цель для хороших сканов ≥ 98%, для текстовых — 100%);
   доля ошибок среди ячеек с `confidence ≥ порога` (по ней калибруется
   `low_confidence_threshold`); доля найденных таблиц.
4. Проверить скорость на целевом железе и подобрать `workers`/`ocr_threads`.

## 13. Что исправлено относительно OCR в «Сверке отчётов 1.2»

| Проблема в 1.2 | Решение в pdfdoc |
|---|---|
| Частые путаницы: «№ пп», «(монтаж}», «[16330» | `fix_ocr_confusions`: безопасные правки (шапка «№ п/п», парность скобок, «[1»→«П» перед цифрами) |
| Увеличение ячеек ×2 → `5→9`, `4→2` даже на чистом скане | Увеличивается только мелкий текст (< 20 px), вокруг текста белое поле |
| Нет выравнивания: перекос 0,5° → 0 позиций | Поиск угла по проекциям (±5°, шаг 0,02°) + OSD для 90/180/270 |
| Одна сетка на страницу, только вертикальные объединения | Несколько таблиц, объединения в обе стороны, рамка листа не считается таблицей |
| Профили колонок по числу колонок (жёсткая схема) | Универсальный OCR ячейки + перепроверка числовых ячеек белым списком |
